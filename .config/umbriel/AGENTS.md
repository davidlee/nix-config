# AGENTS.md: ~/.config/umbriel

Config for [Umbriel](https://github.com/noctalia-dev/umbriel), the Wayland
compositor on Sleipnir. Plain dotfiles, tracked in the `~` repo (the git
worktree is `$HOME`; see `~/flakes/CLAUDE.md`). Nix installs the compositor
only; it does not generate this config.

`NOTES.md` has current work, the open upstream PR and loose threads.

## Which file owns what

Files follow the seams of Umbriel's docs (`docs/user/<page>.md`, linked at
the top of each file), with one exception: `apps.toml`, a concern file.

| file | owns | docs page |
|---|---|---|
| `config.toml` | entry point: `[include]`, `[general]` (autostart), `[environment]`; include order and precedence in its header | configuration |
| `input.toml` | `[input.*]` | input |
| `outputs.toml` | `[output.*]` | outputs |
| `layout.toml` | `[layout.*]`, `[workspaces]`, hand-written `[[workspace]]`, `[overview]` | layout, workspaces, workspaces-overview |
| `appearance.toml` | `[appearance.*]` and window rules that set decoration sizes. No colours | appearance |
| `gruvbox.toml` | the palette: every `[colors.*]`, and window rules that only set colours (state borders). Optional include | appearance |
| `animation.toml` | `[animation.*]` | animation |
| `binds.toml` | `[keybinds]` for the session, windows, layout, workspaces | keybinds, actions |
| `rules.toml` | window rules for how windows open and render; `[[layer_rule]]` | window-rules, layer-rules |
| `apps.toml` | apps reached by a key: launchers, raise-or-run, and per scratchpad its `[[scratchpad]]` and window rules. Its binds share one `[keybinds]` table at the top (TOML allows one per file) | scratchpad, keybinds |
| `workspaces.toml` | generated by `scripts/named-workspace`; optional include | workspaces |

A new setting goes in the file that owns its section. Comments explain a
choice that isn't obvious; they don't restate the docs.

## Where things are

```
~/.config/umbriel/          this config (Umbriel reads only config.toml; includes are listed there)
  scripts/                  helpers bound by absolute path from binds.toml / apps.toml
~/.local/src/umbriel/       upstream source checkout (origin: noctalia-dev/umbriel)
  docs/user/*.md            user docs: configuration, keybinds, actions, scratchpad, window-rules, ipc …
  CONTRIBUTING.md           build, test (`just test`, `just check`), commit conventions
~/flakes/features/compositor.nix   the `umbriel` feature (NixOS module from the flake input)
~/flakes/flake.nix                 the `umbriel` input; its lock pins the running version
```

Online docs: <https://docs.noctalia.dev/umbriel/>. They track upstream `main`.
The local checkout may be newer than the pinned version, so check the source at
the locked revision (`nix flake metadata ~/flakes`) when behaviour disagrees with
the docs.

## Working here

- **Validate** after every edit: `umbriel config validate`. `umbriel config
  schema` lists every accepted key.
- **Reload** is automatic: Umbriel watches the config and its includes. Check
  `journalctl --user -u umbriel.service` for `config reloaded` or errors.
- **Actions:** `umbriel msg --help` lists them. Arguments are separate argv
  words: `umbriel msg window-focus <id>`, never `"window-focus <id>"` or
  `action:arg`. Bind strings in TOML use the same space-separated form.
- **Inspect:** `umbriel windows --json`, `umbriel focused-window`,
  `umbriel workspaces`, `umbriel outputs`.
- **Prefer native features to scripts.** Upgrades add mechanisms that make
  scripts redundant (`spawn_when_empty` replaced `scratchpad-spawn`). Check the
  docs and `umbriel config schema` before adding or keeping one.
- **Scripts** in `scripts/` must lint clean: shellcheck, and for Python
  `nix run 'nixpkgs#ruff' -- check` and `-- format --check` (ruff is not on
  PATH; `ruff.toml` sets the line length). `test_raise_cycle_or_spawn.py`
  runs with `python3 -B -m unittest` from `scripts/`; its `Main` tests run the
  script against a fake `umbriel` on PATH and assert the argv it sends.
- **Upstream bugs:** reproduce in the source checkout with a harness check
  (`just check <name>`) on a branch, red before green. The user raises the PR.
  Don't run a patched umbriel day to day; record the workaround in `NOTES.md`.
