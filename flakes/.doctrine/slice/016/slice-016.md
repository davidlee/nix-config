# Render malebolge's room door file

## Context

satan:SL-027 (`doctrine show SL-027` in `~/dev/satan`) runs malebolge's
interactive daemon in a **room profile**: a jail without network whose coding
tools run in oubliette room `assistant`, as room user `satan`. The daemon finds
the room through a **door file**, a TOML file named by `MALEBOLGE_DOOR`
(satan:DEC-077; SL-027 design §4.3, §4.8). satan:DEC-077 says home-manager
renders it "from one attrset beside the runner's `[door]`", and SL-027 §4.8 and
sec-6 assigned it to flakes:SL-015. SL-015 never scoped it (its scope, design
and plan say nothing of a door file). This slice is the missing owner.

```
features/satan/runner.nix (home-manager)
  room door data (one attrset) ──┬──> satan-runner config.toml [door]   (exists; user agent, malebolge.key)
                                 └──> ~/.config/malebolge/door.toml      (new; user satan, malebolge-vm.key)
                                          │ stable path, read-only bind
                                          ▼
  ~/dev/satan flake.nix: jailed-malebolge room jail ── MALEBOLGE_DOOR ──> daemon: onlyKeys + readRoomDoor
```

The file the daemon expects (SL-027 design §4.3):

```toml
[door]
room = "assistant"
user = "satan"
known_hosts = "/var/lib/capsule/room/assistant/known_hosts"
host_key_alias = "assistant"
identity = "/home/david/.ssh/malebolge-vm.key"
home = "/home/satan"
```

Keys: satan `ROOM_DOOR_KEYS` (`room user known_hosts host_key_alias identity`)
plus `home`; any other key is refused by the parser (`onlyKeys`). No
`ssh_config`: the jail renders its own (satan:DEC-075).

## Scope & Objectives

- In `features/satan/runner.nix`: factor the room-door facts both doors share
  (`room`, `known_hosts`, `host_key_alias`) into one attrset; the runner's
  `door` and the new door are built from it, each adding its own `user` and
  `identity` (and `home` for the new one). The runner's rendered
  `config.toml` stays byte-identical.
- Render the door file to a **stable path** with `xdg.configFile`, as the
  feature already does for `~/.config/malebolge/gateway-models.json`
  (the store path moves on every rebuild): proposed
  `~/.config/malebolge/door.toml`.
- A behaviour test: the rendered file has exactly the satan parser's keys,
  and its shared values equal the runner's.
- Hand the path back to satan:SL-027 (its `malebolgeDoorFile`), and the
  correction that flakes:SL-016, not SL-015, owns the render.

## Non-Goals

- **The vm-mode key.** `~/.ssh/malebolge-vm.key` is generated by hand by the
  user (`ssh-keygen`), like the runner's `malebolge.key`. No key material or
  key generation in this repo (POL-001). The file render only names its path.
- **Fleet.** `rooms.assistant.users.satan` and its public key in
  `/srv/fleet/flake.nix`, and oubliette IMP-023's `repos.readers`: SL-027's and
  oubliette's.
- **The jail.** `jailed-malebolge`'s room profile, its binds and
  `MALEBOLGE_DOOR`: `~/dev/satan/flake.nix` (SL-027).
- **One source of room data** shared with the fleet (satan IMP-044): the
  literals stay hand-copied, as the runner's already are.

## Risks, assumptions, open questions

- **OQ-1, `host_key_alias` (settled at scoping):** the runner uses
  `room-${room}`; SL-027's sample says `"assistant"`.
  `/var/lib/capsule/room/assistant/known_hosts` names its one host
  `room-assistant` (checked 2026-10-20), so the alias is `room-assistant` for
  both doors, and SL-027's sample is wrong (told to satan).
- **OQ-2, path:** `~/.config/malebolge/door.toml` beside `gateway-models.json`
  vs `~/.config/satan-runner/`. The file is the interactive daemon's, not the
  runner's, which points to `~/.config/malebolge/`. SL-027 must use the same
  literal.
- **OQ-3, test home:** the feature has no test today; find how this repo
  tests a home-manager render (eval check vs script test).
- **A-1:** the room user's home is `/home/satan` (SL-027 §4.8); a fleet
  literal, hand-copied.
- **Risk:** the door file names a key that does not exist until the user
  creates it; the daemon fails at connect, not at render. Acceptable: SL-027's
  launcher can pre-flight it.
