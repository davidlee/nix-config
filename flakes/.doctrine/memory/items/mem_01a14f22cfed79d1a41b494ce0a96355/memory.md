Two traps when a jail runs a binary built on the host outside Nix (e.g. `cargo install` doctrine):

1. **File binds go stale.** A bwrap bind of a single file pins one inode. `cargo install` writes a new file and renames it over the old one, so the jail keeps the deleted file. Hooks then fail with ENOENT until the jail restarts (doctrine IMP-249). Bind a *directory* instead: a renamed-in file shows up immediately. Give the binary its own install root so that directory holds nothing else (`cargo install --root ~/.local/share/doctrine`). Don't bind over `~/.cargo/bin`: that exposes every host cargo install and hides the jail's own persisted `~/.cargo`. Verify with a rename while a jail runs, not just launcher text.

2. **The store closure is missing.** jail-nix (`bind-nix-store-runtime-closure`) exposes only the jail's own closure. A cargo-built ELF links specific store paths (glibc `ld-linux`, gcc-lib via RUNPATH). Without them, `command -v` finds the binary but running it gives "command not found" (ENOENT from the interpreter). `elfClosureBinds` in `flakes/agents/jailed-agents.nix` binds interpreter + RUNPATH closure (`nix-store -qR` on the host) as runtime args appended to `RUNTIME_ARGS` (IMP-052: off the bwrap line, which quotient's form check needs plain). It runs at launch, so a reinstall built by a different toolchain needs a relaunch.

Current wiring (2026-11-04, SL-023 closed out at PHASE-07): the host PATH leads with `~/.local/share/doctrine/bin` (PHASE-01: `modules/user-bin-path.nix`, read by pam on Linux and `home.sessionPath` on darwin; DEC-107), ahead of `~/.local/bin`, whose `doctrine` symlink is gone. In jails, `hostDoctrine` (default on) binds the dir read-only at its own host path, `"$HOME/.local/share/doctrine/bin"`, as a runtime arg (a static bind under `~` would be hidden by the persisted home), and adds it to PATH (DEC-110). A Nix-built doctrine, if passed as `nixDoctrine`, is bound with its closure at `/run/doctrine-nix-bin`, never on PATH (DEC-109). Jails on an older `agents` pin still bind only `/run/doctrine-bin`, so the host path baked by `doctrine install` does not exist in them (IMP-060).
