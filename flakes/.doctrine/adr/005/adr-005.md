# ADR-005: Evaluation coverage distinguishes off from parked

## Context

An unselected feature is never evaluated, so it can silently drift against
nixpkgs updates. `hyprland.nix` (`hyprlandPlugins.hyprexpo` removed) and
`kmscon.nix` (`services.kmscon.fonts` removed) broke this way; both are
evaluation failures. The goal "turn it back on later" needs drift to be
visible.

A single target with every feature on is not sound: some features are
mutually exclusive (two greeters), and some are platform-specific.

## Decision

1. **Off** = supported, not selected on a host. Every non-parked feature is
   covered by at least one explicit, valid evaluation target for its
   supported platforms.
2. **Parked** = covered by no target and promised nothing (today: commented
   imports).
3. Targets are a small handwritten set, not a generated matrix. They are
   outside the switch path: a broken off feature never blocks building or
   switching a host.
4. A target forces the system / Home Manager activation / darwin system
   derivation, not merely an option or output listing.
5. Coverage means "evaluates", not "builds" or "works at runtime". An
   upstream compile failure stays undetected until built.
6. A selected feature that projects no module into any evaluation of its host
   is an error. How platform scope is declared (e.g. linux-only Home Manager
   features on darwin) is left open; no support metadata until needed.

## Consequences

### Positive

- Re-enabling an off feature is cheap: it was evaluated recently.
- "Maintained or not" gets a concrete, checkable meaning without metadata.

### Negative

- Evaluation targets are another thing to keep valid.

### Neutral

- Building off features is out of scope.

## Verification

- Targets live in the flake output `coverage`, off every switch path and
  outside `just drvs`; `just coverage` forces each. `nix flake check` warns
  about the unknown output; that is expected.
- Spike includes one coverage target that selects a feature Sleipnir has off.
