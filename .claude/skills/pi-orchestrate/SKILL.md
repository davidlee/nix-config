# Orchestrating pi workers

Run `quotient help orchestrate` and follow it: it is the general guide
(probing the form, roles by capability, briefs, recovering a stopped run,
verification that stays yours). The per-run maxima and the profiles table are
in the server's instructions. This skill adds only the doctrine bindings.

## Doctrine bindings

- It layers on the governing stage (/phase-plan, /execute, /code-review); it
  changes who does the work, not which work is done or which gates apply.
- Briefs cite the phase's criteria ids (EN/EX/VT) and the design references.
- Doctrine state is always yours, never a worker's: phase status, knowledge
  settlement, review dispositions, commits, and any recorded user act.
- An unanticipated obstacle mid-delegation → /consult; review findings →
  adjudicate per /feedback.
- Log each pass (who, profile, cost, outcome) and what pi got wrong in the
  slice notes' review-passes section; durable gotchas → /record-memory.
